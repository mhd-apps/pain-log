# 痛み日誌

慢性的な痛みを記録するための、スマートフォン向けWebアプリ（PWA）です。

診察のときに「いつ・どのくらい・何をしていたときに痛んだか」を医師へ示すことを目的にしています。

## 設計の考え方

このアプリでいちばん大事にしているのは、**痛い最中でも3秒で記録できる**ことです。

- アプリを開いた最初の画面が、そのまま記録画面です。ログインもメニューもありません
- 必須の入力は「痛みの強さ（0〜10）」だけ。数字を2つタップすれば記録は完了です
- 時刻は自動で記録されます（あとから直すこともできます）
- そのほかの項目はすべて任意です。あとから記録一覧を開いて追記できます
- 空欄があっても記録は成立します
- **痛い最中に記録できなくても大丈夫です。** 落ち着いてから、時刻を指定して記録できます

「連続◯日記録中」のようなゲーム的な演出や、記録が途切れたことを責める表示は、意図的に一切入れていません。**途切れたら、また始めればよい**という考え方で作られています。

## プライバシーについて

**記録したデータは、すべてお使いの端末の中だけに保存されます。**

- サーバーへの送信は一切ありません（外部通信をしない設計です）
- 開発者を含め、誰も記録を見ることはできません
- インターネットに接続していなくても、すべての機能が使えます

そのため、Webに公開しても記録の内容が外に漏れることはありません。

ただし裏を返すと、**ブラウザのデータを消去したり、機種変更したりすると記録も消えます。** 設定画面から定期的にバックアップを取ってください（後述）。

## 画面の説明

### 記録（最初の画面）

**数字を2つタップすると記録されます。** 色は 0＝薄い青 から 10＝濃い赤 へ変化します。

- 痛みに幅があるときは、**いちばん弱いときと強いときを1つずつ**タップします（例：5と7で「5〜7」）
- 強さが変わらないときは、**同じ数字を2回**タップします（例：3と3で「3」）
- 2つ目をタップすると「記録しました」と表示されます。**ここで終わりにして構いません**
- 続けて記録するときは、また数字を2つタップするだけです

1つ目をタップした時点で内部的には保存されています。**痛みで中断してしまっても、選んだ数字が消えることはありません。** その場合はその数値だけの記録として残ります。

アプリを閉じて開き直したときは、選びかけの状態はリセットされ、次のタップから新しい記録になります。

幅で記録したものは、ふりかえりや受診用の出力では次のように扱われます。

| 項目 | 「5〜7」の場合に使う値 |
| --- | --- |
| 最大強度・カレンダーの色 | 上限の **7** |
| 平均強度 | 真ん中の **6** |
| 強い痛み（7以上）の一覧 | 上限が7以上なら対象 |

余裕があるときだけ「詳細を追加する（任意）」を押すと、持続時間・痛みの性質・部位・痛みの前後にあったこと・排尿の様子・月経周期・頓服・メモを追加できます。

### あとから記録する

痛みが強いときは、記録する余裕がないことのほうが多いと思います。そのための入口が、記録画面の下にある **「さっきの痛みをあとから記録する」** です。

1. 「30分前」「1時間前」「2時間前」「3時間前」から選ぶ（正確な日時を直接入力することもできます）
2. 痛みの強さを2つタップすると、その時刻の記録として保存されます（同じ数字を2回なら単独の値）

痛みが治まってから、思い出して記録すれば十分です。**その場で記録できなかったことを気にする必要はありません。**

なお、これから先の日時は選べないようになっています（痛みは過去にあったものなので）。

### 一覧

日付ごとに記録が並びます。詳細が未記入の記録には控えめな点（●）が付き、タップすると後から追記できます。強さの変更や削除もここから行えます。

強さを変えるときも、記録画面と同じように**数字を2つタップ**します。

**日時の修正もここからできます。** 記録をタップして開くと「日時（痛みがあった時刻に直せます）」があるので、実際に痛かった時刻に直してください。直すと一覧の並び順も自動で入れ替わります。

### ふりかえり

- 直近30日の記録件数・平均強度・最大強度
- カレンダー（その日のいちばん強かった痛みを色で表示）
- 時刻別の分布（何時ごろに出やすいか）
- 月経周期との重なり
- 「痛みの前後にあったこと」の集計

集計は「同時に記録された回数」を中立に示すもので、原因を断定するものではありません。判断は医師にご相談ください。

### 出力（受診用）

期間を選んで、診察に持っていく資料を作れます。

- **PDFを作成 / 印刷する** … 印刷ダイアログで「PDFに保存」を選ぶと、A4一枚のPDFになります。サマリー、カレンダー、強い痛み（7以上）の一覧が入ります
- **CSVをダウンロード** … 全項目を表計算ソフトで開ける形式で保存します

### 設定

- 夜のふりかえり通知のオン／オフ（初期状態はオフ）
- データのバックアップ（JSON書き出し・復元）

## 開発環境で動かす

Node.js 20以上が必要です。

```bash
npm install
```

```bash
npm run dev
```

表示された `http://localhost:5173` をブラウザで開いてください。

本番用にビルドする場合。

```bash
npm run build
```

ビルド結果を手元で確認する場合。

```bash
npm run preview
```

## スマホのホーム画面に追加する

ホーム画面に追加すると、アドレスバーのない専用アプリのように起動できます。記録までの手数が減るので、**追加して使うことを強くおすすめします。**

### iPhone / iPad（Safari）

Safariで開く必要があります。ChromeなどSafari以外のブラウザでは追加できません。

1. **Safari** でアプリのURLを開く
2. 画面下の中央にある **共有ボタン**（□に↑が乗ったマーク）をタップ
3. メニューを下にスクロールして **「ホーム画面に追加」** をタップ
4. 名前を確認して、右上の **「追加」** をタップ

ホーム画面にアイコンが追加されます。

### Android（Chrome）

1. **Chrome** でアプリのURLを開く
2. 画面下部に「アプリをインストール」というバナーが出たら、それをタップ
3. バナーが出ない場合は、右上の **︙（縦三点）** メニュー → **「アプリをインストール」**（または「ホーム画面に追加」）をタップ
4. **「インストール」** をタップ

### アプリの更新について

新しい版を公開すると、**アプリを開いたときに自動で更新されます。** ホーム画面のPWAは「閉じる」操作が分かりにくいため、強制終了は不要な作りにしてあります。

具体的には、アプリを再び前面に出したタイミングで新しい版がないかを確認し、あれば適用して画面を読み込み直します。更新は数秒で終わります。

記録の途中で更新が入っても、**1つ目にタップした数字はすでに保存されているため失われません。**

### 注意

ホーム画面のアイコンから起動したアプリと、ブラウザで開いたアプリとで、**記録が別々に保存される場合があります。** 混乱を避けるため、追加したあとはホーム画面のアイコンからのみ使うことをおすすめします。

すでにブラウザで記録してしまった場合は、設定画面からJSONを書き出し、ホーム画面のアプリ側で読み込んでください。

## バックアップのしかた

記録は端末の中だけにあるため、こまめなバックアップが安心です。

**書き出し**：設定 → 「全データをJSONで書き出す」。ファイルが保存されるので、iCloudやGoogleドライブ、自分宛てのメールなどに保管しておいてください。

**復元**：設定 → 「JSONから復元する」で、保存しておいたファイルを選びます。

※ 復元すると、そのとき端末にある記録はすべて置き換わります。追加ではなく上書きです。

## 通知について

夜に1回だけ「今日の記録をふりかえりませんか」とお知らせする機能です。初期状態ではオフで、設定画面から有効にできます。

痛みが出た瞬間に通知しても意味がないため、**催促のような通知は送りません。**

ブラウザの制約により、この通知は**アプリを開いたときに条件を満たしていれば表示される**しくみです。アプリを閉じている間に届くわけではない点にご注意ください。確実な通知が必要な場合は、スマホの標準アラーム機能を併用してください。

## 公開について

**公開URL: https://mhd-apps.github.io/pain-log/**

GitHub Pagesで公開しています。データはすべて端末内に保存されるため、公開してもプライバシー上の問題は生じません。

### 更新のしかた

`main` ブランチに push すると、GitHub Actions が自動でビルドして公開まで行います（`.github/workflows/deploy.yml`）。手動の作業は不要です。

```bash
git push
```

進行状況はリポジトリの **Actions** タブで確認できます。1〜2分で反映されます。

### サブディレクトリ配信について

GitHub Pagesは `https://mhd-apps.github.io/pain-log/` というサブディレクトリで配信されるため、`vite.config.ts` で `base` を指定しています。

```ts
base: command === 'build' || isPreview ? '/pain-log/' : '/'
```

`vite preview` も本番と同じサブパスで動くようにしてあるので、`npm run preview` で公開時と同じ状態を手元で確認できます（`http://localhost:4173/pain-log/`）。

**リポジトリ名を変えた場合は、この `BASE` の値も合わせて変更してください。** 変えないとアセットが読み込めず真っ白な画面になります。

### 別のサービスを使う場合

Vercel や Netlify はルート配信のため、その場合は `base` の指定を外してください（`base: '/'`）。

※ PWAとして動作させるには **HTTPS** が必要です。GitHub Pages / Vercel / Netlify はいずれも自動でHTTPSになります。

## 技術構成

| 項目 | 使用しているもの |
| --- | --- |
| フレームワーク | React 19 + Vite（TypeScript） |
| データ保存 | IndexedDB（`idb`）— 端末内のみ |
| PWA | `vite-plugin-pwa`（オフライン完全対応） |
| グラフ | `recharts` |
| PDF出力 | 印刷用CSS（`@media print`）＋ ブラウザの印刷機能 |

PDFは日本語フォントの埋め込み問題を避けるため、jsPDFではなく**ブラウザの印刷機能を使う方式**を採用しています。端末に入っている日本語フォントがそのまま使われるため、文字化けが起きません。

起動を速くするため、グラフ関連のコードは「ふりかえり」画面を開いたときにだけ読み込まれます（オフラインでも使えるよう、事前にキャッシュされます）。
