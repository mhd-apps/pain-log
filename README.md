# 痛み日誌

慢性的な痛みを記録するための、スマートフォン向けWebアプリ（PWA）です。

診察のときに「いつ・どのくらい・何をしていたときに痛んだか」を医師へ示すことを目的にしています。

## 設計の考え方

このアプリでいちばん大事にしているのは、**痛い最中でも3秒で記録できる**ことです。

- アプリを開いた最初の画面が、そのまま記録画面です。ログインもメニューもありません
- 必須の入力は「痛みの強さ（0〜10）」だけ。数字をタップした瞬間に保存されます
- 時刻は自動で記録されます
- そのほかの項目はすべて任意です。あとから記録一覧を開いて追記できます
- 空欄があっても記録は成立します

「連続◯日記録中」のようなゲーム的な演出や、記録が途切れたことを責める表示は、意図的に一切入れていません。**途切れたら、また始めればよい**という考え方で作られています。

## プライバシーについて

**記録したデータは、すべてお使いの端末の中だけに保存されます。**

- サーバーへの送信は一切ありません（外部通信をしない設計です）
- 開発者を含め、誰も記録を見ることはできません
- インターネットに接続していなくても、すべての機能が使えます

そのため、Webに公開しても記録の内容が外に漏れることはありません。

ただし裏を返すと、**ブラウザのデータを消去したり、機種変更したりすると記録も消えます。** 設定画面から定期的にバックアップを取ってください（後述）。

## 画面の説明

### 記録（最初の画面）

0〜10の大きなボタンをタップするだけで記録されます。色は 0＝薄い青 から 10＝濃い赤 へ変化します。

タップしたら「記録しました」と表示されます。**ここで終わりにして構いません。**

余裕があるときだけ「詳細を追加する（任意）」を押すと、持続時間・痛みの性質・部位・痛みの前後にあったこと・排尿の様子・月経周期・頓服・メモを追加できます。

### 一覧

日付ごとに記録が並びます。詳細が未記入の記録には控えめな点（●）が付き、タップすると後から追記できます。強さの変更や削除もここから行えます。

### ふりかえり

- 直近30日の記録件数・平均強度・最大強度
- カレンダー（その日のいちばん強かった痛みを色で表示）
- 時刻別の分布（何時ごろに出やすいか）
- 月経周期との重なり
- 「痛みの前後にあったこと」の集計

集計は「同時に記録された回数」を中立に示すもので、原因を断定するものではありません。判断は医師にご相談ください。

### 出力（受診用）

期間を選んで、診察に持っていく資料を作れます。

- **PDFを作成 / 印刷する** … 印刷ダイアログで「PDFに保存」を選ぶと、A4一枚のPDFになります。サマリー、カレンダー、強い痛み（7以上）の一覧が入ります
- **CSVをダウンロード** … 全項目を表計算ソフトで開ける形式で保存します

### 設定

- 夜のふりかえり通知のオン／オフ（初期状態はオフ）
- データのバックアップ（JSON書き出し・復元）

## 開発環境で動かす

Node.js 20以上が必要です。

```bash
npm install
```

```bash
npm run dev
```

表示された `http://localhost:5173` をブラウザで開いてください。

本番用にビルドする場合。

```bash
npm run build
```

ビルド結果を手元で確認する場合。

```bash
npm run preview
```

## スマホのホーム画面に追加する

ホーム画面に追加すると、アドレスバーのない専用アプリのように起動できます。記録までの手数が減るので、**追加して使うことを強くおすすめします。**

### iPhone / iPad（Safari）

Safariで開く必要があります。ChromeなどSafari以外のブラウザでは追加できません。

1. **Safari** でアプリのURLを開く
2. 画面下の中央にある **共有ボタン**（□に↑が乗ったマーク）をタップ
3. メニューを下にスクロールして **「ホーム画面に追加」** をタップ
4. 名前を確認して、右上の **「追加」** をタップ

ホーム画面にアイコンが追加されます。

### Android（Chrome）

1. **Chrome** でアプリのURLを開く
2. 画面下部に「アプリをインストール」というバナーが出たら、それをタップ
3. バナーが出ない場合は、右上の **︙（縦三点）** メニュー → **「アプリをインストール」**（または「ホーム画面に追加」）をタップ
4. **「インストール」** をタップ

### 注意

ホーム画面のアイコンから起動したアプリと、ブラウザで開いたアプリとで、**記録が別々に保存される場合があります。** 混乱を避けるため、追加したあとはホーム画面のアイコンからのみ使うことをおすすめします。

すでにブラウザで記録してしまった場合は、設定画面からJSONを書き出し、ホーム画面のアプリ側で読み込んでください。

## バックアップのしかた

記録は端末の中だけにあるため、こまめなバックアップが安心です。

**書き出し**：設定 → 「全データをJSONで書き出す」。ファイルが保存されるので、iCloudやGoogleドライブ、自分宛てのメールなどに保管しておいてください。

**復元**：設定 → 「JSONから復元する」で、保存しておいたファイルを選びます。

※ 復元すると、そのとき端末にある記録はすべて置き換わります。追加ではなく上書きです。

## 通知について

夜に1回だけ「今日の記録をふりかえりませんか」とお知らせする機能です。初期状態ではオフで、設定画面から有効にできます。

痛みが出た瞬間に通知しても意味がないため、**催促のような通知は送りません。**

ブラウザの制約により、この通知は**アプリを開いたときに条件を満たしていれば表示される**しくみです。アプリを閉じている間に届くわけではない点にご注意ください。確実な通知が必要な場合は、スマホの標準アラーム機能を併用してください。

## インターネットに公開する

データはすべて端末内に保存されるため、公開してもプライバシー上の問題は生じません。以下のいずれかの方法が使えます。

### Vercel（おすすめ・いちばん簡単）

1. このプロジェクトをGitHubにアップロードする
2. [vercel.com](https://vercel.com) にGitHubアカウントでログイン
3. 「Add New」→「Project」から、該当のリポジトリを選ぶ
4. Framework Presetが **Vite** になっていることを確認して「Deploy」

数十秒でURLが発行されます。以降はGitHubに変更を反映するたびに自動で更新されます。

### Netlify

1. プロジェクトをGitHubにアップロードする
2. [netlify.com](https://netlify.com) にログインし、「Add new site」→「Import an existing project」
3. リポジトリを選び、以下を設定して「Deploy」
   - Build command: `npm run build`
   - Publish directory: `dist`

GitHubを使わない場合は、`npm run build` で生成された `dist` フォルダを [app.netlify.com/drop](https://app.netlify.com/drop) にドラッグ＆ドロップするだけでも公開できます。

### GitHub Pages

GitHub Pagesはリポジトリ名のサブディレクトリ（`https://ユーザー名.github.io/リポジトリ名/`）で公開されるため、`vite.config.ts` に `base` の指定を追加する必要があります。

```ts
export default defineConfig({
  base: '/リポジトリ名/',
  plugins: [ /* ... */ ],
})
```

その後、以下でビルドし、`dist` の中身をリポジトリの `gh-pages` ブランチに公開してください。

```bash
npm run build
```

`gh-pages` パッケージを使うと簡単です。

```bash
npm install -D gh-pages && npx gh-pages -d dist
```

※ PWAとして正しく動作させるには **HTTPS** である必要があります。上記3サービスはいずれも自動でHTTPSになります。

## 技術構成

| 項目 | 使用しているもの |
| --- | --- |
| フレームワーク | React 19 + Vite（TypeScript） |
| データ保存 | IndexedDB（`idb`）— 端末内のみ |
| PWA | `vite-plugin-pwa`（オフライン完全対応） |
| グラフ | `recharts` |
| PDF出力 | 印刷用CSS（`@media print`）＋ ブラウザの印刷機能 |

PDFは日本語フォントの埋め込み問題を避けるため、jsPDFではなく**ブラウザの印刷機能を使う方式**を採用しています。端末に入っている日本語フォントがそのまま使われるため、文字化けが起きません。

起動を速くするため、グラフ関連のコードは「ふりかえり」画面を開いたときにだけ読み込まれます（オフラインでも使えるよう、事前にキャッシュされます）。
